# Space Biology Knowledge Engine: Backend Implementation Guide

## 1. Overview

This document provides a technical specification for building the backend services required to power the Space Biology Knowledge Engine frontend. The goal is to replace the mock API (`src/services/api.ts`) with a live, data-driven backend built with FastAPI, Neo4j, and a Vector Database, orchestrated by a fine-tuned LLM (Gemma).

## 2. System Architecture

As outlined in the project presentation, the recommended architecture is as follows:

-   **Web Framework**: **FastAPI** (Python) for creating robust, high-performance APIs.
-   **Knowledge Graph Database**: **Neo4j** for storing and querying the complex relationships between studies, genes, proteins, etc.
-   **Semantic Search**: A **Vector Database** (e.g., FAISS, Pinecone, Weaviate) to store embeddings of research documents for fast similarity searches.
-   **AI Model**: **Gemma** (fine-tuned) for processing natural language queries, synthesizing answers, and extracting information.
-   **Data Ingestion**: Python scripts using libraries like `SciSpacy` and `BioBERT` for Named Entity Recognition (NER) and Relation Extraction.

## 3. Data Ingestion & Processing Flow

The backend must first ingest and process data from the specified NASA sources (GeneLab, ALSDA, PubSpace, NASA Task Book).

1.  **Data Ingestion**: ETL scripts (Python) will fetch data from the various sources.
2.  **Preprocessing**: Text data from publications will be processed. Use `SciSpacy` or `BioBERT` for NER to identify entities like genes, proteins, species, diseases, etc.
3.  **Relation Extraction**: Identify relationships between the extracted entities (e.g., "Gene A *upregulates* Protein B in *Study C*").
4.  **Data Loading**:
    -   Load the structured entities and their relationships into **Neo4j** to build the knowledge graph.
    -   Create text embeddings for document chunks (e.g., paragraphs from papers) and load them into the **Vector Database** for semantic search.

## 4. API Specification

All endpoints should be prefixed, for example, `/api/v1/`. The frontend expects JSON responses.

---

### **Endpoint: Get Filter Options**

-   **URL**: `/filters`
-   **Method**: `GET`
-   **Description**: Fetches the available options for the dashboard filter dropdowns. These can be dynamically generated by querying the distinct values present in the database.
-   **Success Response (200 OK)**:
    ```json
    {
      "species": ["Rattus Norvegicus", "Mus Musculus", "Homo Sapiens", "Drosophila melanogaster"],
      "exposure": ["Microgravity (ISS)", "Simulated Microgravity", "Radiation", "Hindlimb Unloading"],
      "organSystem": ["Musculoskeletal", "Cardiovascular", "Immune", "Nervous System"]
    }
    ```

---

### **Endpoint: Get Knowledge Graph Data**

-   **URL**: `/knowledge-graph`
-   **Method**: `POST`
-   **Description**: Retrieves nodes and edges for the knowledge graph based on the user's selected filters. The backend should query Neo4j based on these parameters.
-   **Request Body**:
    ```json
    {
      "species": "Rattus Norvegicus",
      "exposure": "Simulated Microgravity",
      "organSystem": "Musculoskeletal"
    }
    ```
-   **Success Response (200 OK)**: A JSON array of elements in a format compatible with Cytoscape.js.
    ```json
    [
      { "data": { "id": "study1", "label": "Rat Bone Loss", "type": "study" } },
      { "data": { "id": "gene1", "label": "Actb", "type": "gene" } },
      { "data": { "id": "gene2", "label": "Cstb", "type": "gene" } },
      { "data": { "source": "study1", "target": "gene1", "label": "downregulates" } },
      { "data": { "source": "study1", "target": "gene2", "label": "upregulates" } }
    ]
    ```

---

### **Endpoint: Get Study Comparison Data**

-   **URL**: `/studies/compare`
-   **Method**: `POST`
-   **Description**: Fetches detailed, side-by-side comparison data for a list of selected study IDs.
-   **Request Body**:
    ```json
    {
      "studyIds": ["study1", "study2"]
    }
    ```
-   **Success Response (200 OK)**: A JSON object where keys are column headers and values are arrays of the data for that column.
    ```json
    {
      "PARAMETER": ["Species", "Exposure", "Duration", "Key Finding"],
      "Rat Bone Loss": ["Rattus Norvegicus", "Simulated Microgravity", "60 days", "Bone density -12.8%"],
      "Mouse Muscle Atrophy": ["Mus Musculus", "Microgravity (ISS)", "30 days", "Muscle mass -22.5%"]
    }
    ```

-   **URL**: `/charts/bone-density` & `/charts/gene-expression`
-   **Method**: `POST`

### **Endpoint: Semantic Search**

-   **URL**: `/search`
-   **Method**: `POST`
-   **Description**: The core AI endpoint. It takes a user's natural language query and returns a synthesized answer with citations.
-   **Backend Logic**:
    1.  Create an embedding of the user's query (`query`).
    2.  Use the embedding to perform a similarity search in the **Vector Database** to find the most relevant document chunks.
    3.  Pass the user's query and the retrieved document chunks as context to the fine-tuned **Gemma LLM**.
    4.  Prompt the LLM to generate a concise answer based *only* on the provided context and to identify which parts of the context were used for the answer (these are the citations).
    5.  Format the LLM's output into the required JSON structure.
-   **Request Body**:
    ```json
    {
      "query": "What are the primary molecular mechanisms affected by microgravity in human cardiovascular cells?"
    }
    ```
-   **Success Response (200 OK)**:
    ```json
    {
      "id": "msg_12345",
      "author": "ai",
      "text": "Microgravity induces several key molecular changes...",
      "citations": [
        { "id": 1, "text": "Versari, S. et al. (2021)... Source: NASA Space Life Sciences Library." },
        { "id": 2, "text": "Zhang, Y. et al. (2019)... Source: PubSpace." }
      ]
    }
    ```

-   **URL**: `/search/greeting`
-   **Method**: `GET`
-   **Description**: Provides the initial welcome message for the Semantic Search chat interface.
-   **Success Response (200 OK)**:
    ```json
    {
        "id": 1,
        "author": "ai",
        "text": "Hello Dr. Carter. I'm ready to assist with your space biology research. How can I help you today?"
    }
    ```
